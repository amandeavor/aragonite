# Changelog 0.11

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.11.0: marks you can hover, and reach from the keyboard

- **The caret looks like the browser's again.** The bar the editor draws used to land on
  half-pixels, so it smeared across two columns (washed out, a touch wide, worse at 125% or 150%
  display scaling), and about half the time it stood one pixel into the next letter. Now it sits on
  whole screen pixels, in the column the browser's own caret uses, as wide as the browser's at your
  display scale.
- **The caret takes the color of the text it's in**, a link's color inside a link, like the
  browser's caret does. `--md-caret-color` now defaults to that; set it if you want one color
  everywhere.
- **Mark decorations can tell you when they're hovered.** Give a mark an `interactive.onHover` and
  it gets called on the way in, with the rect the pointer came through (and every rect the mark
  paints), then once with `null` when the hover ends. It ends when the pointer leaves, the source
  drops the mark, its block scrolls out of range, a new document loads, or the editor unmounts, so a
  card you open on hover always hears when to close.
- **Keyboard users get there too.** The new `decorations.activateAtCaret` command runs the
  `onActivate` of the mark under the caret. It ships without a chord; bind one through
  `keybindings` or call it with `runCommand`.
- **`interactive.onClick` is optional now**, and `interactive` needs at least one of its three
  handlers. A mark with `onClick` takes the click. A hover-only mark lets clicks, drags and
  double-clicks through to the text under it, and keeps the text cursor.
- **Where interactive marks overlap, the shortest range wins**, then the earlier source, for the
  pointer and the keyboard alike. Clickable marks also paint above plain ones (a search highlight,
  say), whatever order their sources registered in.
- **Marks in table cells behave.** A clickable mark keeps its click when another source paints a
  plain mark on the same cell (it used to lose it to whichever came last), and a throwing `onClick`
  there reports the cell's path on the `error` event, not the table's.
- **Upgrade note:** since `onClick` is optional, calling `dec.interactive.onClick(...)` yourself
  needs a `?.` now (TypeScript's `TS2722`, "Cannot invoke an object which is possibly
  'undefined'").
