# Changelog 0.11

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.11.0: marks you can hover, and reach from the keyboard

- **The caret looks like the browser's again.** The bar the editor draws used to land on
  half-pixels, so it smeared across two columns (washed out, a touch wide, worse at 125% or 150%
  display scaling), and about half the time it stood one pixel into the next letter. Now it sits on
  whole screen pixels, in the column the browser's own caret uses, as wide as the browser's at your
  display scale.
- **The caret takes the color of the text it's in**, a link's color inside a link, like the
  browser's caret does. `--md-caret-color` now defaults to that; set it if you want one color
  everywhere.
- **The find bar has a new look** (Finn's): a soft card with one rounded field that holds the match
  count and the case, whole-word and regex toggles. Step and replace stay disabled until there's a
  match, and `--search-bar-top` / `--search-bar-right` move it from its corner (10px each by
  default).
- **The find bar got kinder to keyboards and screen readers.** The match count is announced as it
  changes, and when Replace or All leaves no match, focus moves to the replace field instead of
  getting stuck on a disabled button. In forced-colors mode the field keeps its outline and a
  pressed toggle looks pressed.
- **The open find bar moves only the block controls it actually covers.** A code block's rail, a
  diagram's toolbar or an equation's layout toggle drops below the bar when the bar sits over it,
  including as you scroll a block under it, and every other block's controls stay put. A plugin's
  own top-right hover control opts in with `data-corner-control`.
- **A find bar you've moved with `searchBarAnchor` keeps the editor's colors** in a host with its
  own theme.
- **Inserting a table row above the header, or moving a row into first place, makes that row the
  header.** The old header used to keep the flag on screen while the saved table already read the
  new first row as the header, so a reload showed a different table.
- **Turning a format off across several blocks gives each block the kind its new text reads as.**
  Un-bolding `**#**` leaves a heading, the same as it already did inside one block.
- **An emptied line after a line break no longer saves a stray backslash.** Shift+Enter, a letter,
  then Backspace (or cutting that letter) used to write `abc def\`, which a reload showed as a
  literal backslash. The empty line now behaves like a fresh Shift+Enter line: it's there while
  your caret is, and leaving it (an arrow, a click, a blur) takes it away. **Changed from 0.10.10:**
  the arrows no longer stop on an emptied line after you've left it.
- **Removing an image in live mode leaves nothing behind.** Its toolbar's Remove (and any other
  popover or menu write over a range) used to strand the markers around it, so a linked image left
  `[](u)` and a bold one left `****` on screen.
- **In live mode, the part of a format run you keep stays formatted**, the way a word processor
  does it. Cut from inside `bold` to past `and` in `Some **bold** and words`, and you're left
  with `Some **bo**d words` instead of `Some bod words`. Deleting and dragging work the same, and
  so do italic, strikethrough, code spans and links. Source mode still removes exactly what you
  selected.
- **Copy, cut and drag carry the format they cut through** in live mode, closed at the selection's
  edges (`**ld** an`, not `ld** an`), so pasting gives back what you cut, and dropping or pasting
  formatted text inside another format run joins it cleanly instead of printing `**` on screen.
- **Typing over a link's whole text keeps the link**, and two links with different destinations
  that meet across a deleted range stay two links instead of fusing into one.
- **A selection that ends right where a rule, code block, HTML block or math block starts leaves
  that block alone.** Deleting it used to pull the block's markup into the paragraph above, so a
  rule turned into the text `al---` and a code fence lost its opener. Paragraphs and headings still
  join the way they always did.
- **Typing over a selection that ends on a rule** puts your text in a new paragraph after the rule,
  the way an IME already did, instead of writing `x---`.
- **aragonite works in React.** The new `@voithos-labs/aragonite-react` package gives you
  `<Aragonite>`: a controlled `value` with `onChange` (or `defaultValue` to start uncontrolled), a
  React `header`, every editor prop, and a ref to the editor's handle. It's marked `'use client'`
  for Next, works in StrictMode, and supports React 18 and 19. It ships in lockstep with the core
  package, at the same version.
- **Svelte is an optional peer now**, so a React or Vue app doesn't install a Svelte it never uses.
  Keep `skipLibCheck` on in those apps for now (the core's types still mention Svelte).
- **Writing `source: undefined` keeps the document** instead of emptying it, from Svelte or
  `createEditor` alike.
- **Apps that don't compile Svelte get a prebuilt build automatically.** A React, Vue or plain
  bundler resolves the package to a copy with Svelte compiled in; import
  `@voithos-labs/aragonite/style.css` beside `editor-theme.css`. Svelte apps still get the source
  build, unchanged.
- **A plugin component compiled against a different copy of Svelte says so in dev**, instead of the
  generic "block failed to render".
- **A `searchChange` event** fires once whenever what the find bar shows changes: open or closed,
  the query, the options, the current match, the match count, an error, or the count a replace
  reads out. A regex search fires once its matches land, and a replace-all fires once after its
  last block, so a host outside Svelte can mirror the find state.
- **Inline menu rows can be plain DOM**: `row: { buildDom, destroy }` beside the Svelte component.
- **A plugin view that throws falls back and reports on `error` instead of breaking things.** A menu
  row shows the default row, an inline widget whose `buildWidget` or `isWidget` throws shows its
  source instead of failing its whole block, and a widget or row that throws while it's torn down
  reports instead of leaving an unhandled rejection.
- **`createEditor(target, options)` mounts the editor without a Svelte component.** It hands back
  the editor's usual handle plus `update` (pass changed props) and `destroy`, and `header` takes an
  element. It's the base the framework wrappers build on.
- **Hooks you swap after mount reach the blocks already on screen.** `onRunCode`, `codeMenuItems`
  and `onPasteImage` used to stick with whatever a block mounted with, so adding a run hook later
  painted no run button on code blocks you could already see.
- **Nothing lands after the editor unmounts.** An `insertMarkdown` or image paste still running at
  unmount writes nothing and fires no event, and an `insertMarkdown` overtaken by a `source` swap
  resolves `false` instead of `true`.
- **`imageLoadPolicy` can change after mount.** It always could; the guide used to say otherwise.
- **Mark decorations can tell you when they're hovered.** Give a mark an `interactive.onHover` and
  it gets called on the way in, with the rect the pointer came through (and every rect the mark
  paints), then once with `null` when the hover ends. It ends when the pointer leaves, the source
  drops the mark, its block scrolls out of range, a new document loads, or the editor unmounts, so a
  card you open on hover always hears when to close.
- **Keyboard users get there too.** The new `decorations.activateAtCaret` command runs the
  `onActivate` of the mark under the caret. It ships without a chord; bind one through
  `keybindings` or call it with `runCommand`.
- **`interactive.onClick` is optional now**, and `interactive` needs at least one of its three
  handlers. A mark with `onClick` takes the click. A hover-only mark lets clicks, drags and
  double-clicks through to the text under it, and keeps the text cursor.
- **Where interactive marks overlap, the shortest range wins**, then the earlier source, for the
  pointer and the keyboard alike. Clickable marks also paint above plain ones (a search highlight,
  say), whatever order their sources registered in.
- **Marks in table cells behave.** A clickable mark keeps its click when another source paints a
  plain mark on the same cell (it used to lose it to whichever came last), and a throwing `onClick`
  there reports the cell's path on the `error` event, not the table's.
- **Upgrade note:** since `onClick` is optional, calling `dec.interactive.onClick(...)` yourself
  needs a `?.` now (TypeScript's `TS2722`, "Cannot invoke an object which is possibly
  'undefined'").
